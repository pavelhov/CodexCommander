Компаньон для macOS выводит наиболее полезное состояние CodexCommander в строку меню, не заменяя
прокси и не дублируя веб-панель. Это нативное приложение на Swift/AppKit, которое обращается
только к экземпляру CodexCommander, запущенному на том же Mac.

## Установка

Откройте [GitHub Releases](https://github.com/pavelhov/CodexCommander/releases) и скачайте текущую
универсальную предварительную версию для Mac с Intel и Apple Silicon. Выберите файл
`CodexCommander-<version>-macos-universal.zip` и соответствующий файл контрольной суммы `.sha256`.

Эта предварительная версия подписана ad-hoc и не нотарифицирована. Распакуйте ZIP и переместите `CodexCommander.app` в папку «Программы». При первом запуске нажмите приложение, удерживая Control, и выберите «Открыть». Если macOS по-прежнему блокирует запуск, выберите «Системные настройки» → «Конфиденциальность и безопасность» → «Все равно открыть». Не отключайте Gatekeeper.

Чтобы собрать приложение самостоятельно, следуйте приведённой ниже инструкции [Сборка из исходного кода](#сборка-из-исходного-кода).

## Режимы запуска

- **Desktop** — приложение меню открывается при входе, выполняет явный Start, запускает прокси или
  подключается к нему и направляет управляемый Codex через этот прокси. Внешний провайдер,
  настроенный пользователем, сохраняется.
- **Headless** — запускается только отдельно установленная служба `ccx service`, без приложения меню.
- **Off** — автозапуск выключен. При новом ручном запуске приложение выполняет явный Start и
  направляет управляемый Codex через прокси; `ccx start` выполняет тот же переход.

В этом руководстве **восстановить нативную маршрутизацию** означает удалить только маршрутизацию,
которой владеет CodexCommander. Внешний провайдер Codex, настроенный пользователем, не изменяется.

Переключатель **Launch at Login** находится в строке запуска. Если требуется разрешение, приложение
открывает настройки Login Items macOS. Переключатель не устанавливает, не останавливает и не удаляет
фоновую службу.

Видимое приложение и фоновый прокси работают независимо. Когда панель CodexCommander активна,
**Quit Menu Bar** (`⌘Q`) закрывает только
UI компаньона и оставляет маршрутизацию активной. **Stop CodexCommander and Quit…** (`⌥⌘Q`) — явный
разрушительный выход: после подтверждения он восстанавливает нативную маршрутизацию Codex,
останавливает прокси и службу и закрывает компаньон только после подтверждения остановки.

## Что показывает панель

- **Состояние прокси** — показывает, работает ли процесс. Работающий сервер не доказывает,
  что стартовая синхронизация завершена или что Codex использует прокси.
- **Готовность** — отражает стартовую синхронизацию каталога как **Checking**, **Starting**, **Ready**,
  **Startup failed** или **Unavailable**. Этот сигнал не зависит от состояния прокси.
- **Маршрут Codex** — показывает, направлен ли Codex через CodexCommander, нативный OpenAI или
  другой пользовательский маршрут. Работающий прокси сам по себе не означает, что Codex его использует.
- **Активные запросы прокси** — текущее число выполняющихся запросов и строки turn с
  моделью/провайдером. Дочерний запрос отображается вложенным, только когда CodexCommander может
  подтвердить выполняющегося родителя по метаданным запроса; иначе он показывается как отдельный
  turn субагента. После завершения модельного запроса строка исчезает, даже если Codex сохраняет
  дочерний поток бездействующим для последующей работы. Это не постоянное представление жизненного
  цикла агентов Codex; компаньон не выдумывает историю состояний «в очереди», «на проверке»,
  «ограничено по частоте» или «завершено».
- **Квоты провайдеров** — окна и время сброса, которые сообщает провайдер, если они доступны.
  Для OpenCode Go показываются опубликованные лимиты и локальные наблюдения, а не выдуманный
  текущий баланс. Отсутствующие данные показываются как недоступные, а не как нулевое
  использование или неограниченная ёмкость.
- **Dashboard и Logs** — открывают соответствующее локальное представление панели в браузере
  по умолчанию и передают одноразовое разрешение запуска для изменений, включая Apply каталога.
- **Управление** — открывает вкладку Accounts или API Keys выбранного провайдера. OAuth, ввод
  API-ключа, повторная аутентификация, переключение аккаунтов и настройка провайдера остаются
  в веб-панели.
- **Restart ChatGPT to load models** — постоянная неаварийная карточка, которая появляется, если
  работающие фоновые процессы Codex всё ещё используют прежний список моделей. Прокси CodexCommander
  остаётся исправным и продолжает работать.
- **Show restart steps…** — объясняет рекомендуемую границу перезагрузки: полностью завершите ChatGPT,
  снова откройте его и затем начните новую задачу. Из этой карточки приложение меню не выполняет
  принудительный перезапуск фоновых воркеров.
- **Start Proxy** — запускает прокси или подключается к нему, включает интеграцию Codex и направляет
  Codex через работающий endpoint.
- **Stop Proxy…** — всегда запрашивает подтверждение и восстанавливает нативную маршрутизацию Codex
  до остановки прокси. Если нативный маршрут нельзя проверить, прокси и служба продолжают работать.
  Приложение строки меню остаётся открытым.
- **Restart Proxy…** — запрашивает подтверждение и выполняет тот же безопасный цикл stop→start, что
  и CLI. Сначала восстанавливает нативную маршрутизацию Codex, затем завершает старый прокси, а на
  явном этапе Start запускает новый и снова направляет через него Codex. При ошибке Codex остаётся
  на нативном маршруте.
- **Restore Native Codex** — переключает Codex на нативную маршрутизацию OpenAI, не останавливая прокси.
- **Route Codex Through Proxy** — направляет Codex через уже работающий прокси CodexCommander, не
  перезапуская его.
- **Quit Menu Bar** — закрывает только UI компаньона; прокси, служба и маршрутизация клиентов не
  останавливаются. Когда панель активна, это безопасное действие `⌘Q`.
- **Stop CodexCommander and Quit…** — после подтверждения сначала восстанавливает нативную
  маршрутизацию Codex, затем останавливает фоновый прокси и службу и выходит только после
  подтверждённой остановки. При ошибке компаньон остаётся открытым и показывает её. Когда панель
  активна, сочетание клавиш — `⌥⌘Q`.

При выборе любого действия маршрута сразу под заголовком появляется карточка состояния. Она
показывает индикатор, прошедшее время и реальные этапы: **Changing route** и **Confirming route**.
Во время операции кнопки маршрута и жизненного цикла отключены; в состоянии
ожидания отключена кнопка уже активного маршрута. Прогресс остаётся видимым до завершения, а
итоговый успех или ошибка — пока пользователь не нажмёт **Dismiss** или не начнёт другую операцию.

После успешного **Restore Native Codex** или **Route Codex Through Proxy** полностью завершите
ChatGPT, снова откройте его и начните новую задачу. Маршрут уже сохранён и подтверждён, но работающий
хост ChatGPT/Codex может всё ещё использовать предыдущий маршрут.

Нативный escape намеренно узок: он удаляет только принадлежащую CodexCommander маршрутизацию,
отмеченную его маркером в <code>$CODEX_HOME/config.toml</code>. Он не изменяет задачи, историю,
аутентификацию Codex или процесс прокси. Для него не нужны ни команда `repair`, ни база данных координатора.
Сгенерированные каталоги и кэши могут остаться на диске, но native Codex больше на них не ссылается.

`codexcommander-journal.json` — защищённая контрольная точка восстановления, а не отдельная настройка
маршрута. Она позволяет отличить точную запись CodexCommander от более поздних пользовательских
изменений после прерывания. Повторный **Route Codex Through Proxy** является безопасным no-op, если
эта точка всё ещё принадлежит подтверждённому работающему прокси, evidence профиля совпадает, а
управляемый маршрут остаётся целым. Посторонние изменения настроек Codex после sync допускаются.
Если владение маршрутом изменено, стало custom или неоднозначным либо не может быть безопасно
доказано, CodexCommander не угадывает и оставляет текущий маршрут без изменений. Не удаляйте и не
редактируйте journal вручную.

ChatGPT отображается первым и раскрытым, когда доступен его отчёт о квоте. Kimi и Grok
показываются в виде свёрнутых сводок. Если настроенный провайдер с поддержкой квот не вернул
отчёт, он не исчезает: строка показывает **Квота недоступна**, а в раскрытом виде доступен переход
к настройкам провайдера. Если связанный вход Grok или Kimi CLI устарел, строка вместо этого
показывает **Требуется обновить вход** и предлагает запустить `grok` или `kimi`, а затем нажать
**Обновить**. Отклонённый вход показывается как **Требуется войти**, а сетевой или внешний сбой —
как **Временно недоступно**. Это фиксированные безопасные для конфиденциальности коды причин от
локального прокси, а не исходные ошибки провайдера. **Показать всех провайдеров** открывает полное
рабочее пространство Providers.

## Обновления каталога агентов

При открытии приложение автоматически синхронизирует каталог моделей Codex с провайдерами,
настроенными в CodexCommander. Если процессы Codex не запущены, новый список будет готов к следующей
задаче Codex. Если долгоживущий процесс загрузил прежний список, CodexCommander продолжает работать,
а в панели остаётся неаварийная карточка **Restart ChatGPT to load models**.

Выберите **Show restart steps…**, полностью завершите ChatGPT, снова откройте его и затем начните новую
задачу. Это рекомендуемый и наиболее предсказуемый способ заменить прежний воркер. CodexCommander и
приложение меню всё это время продолжают работать.

Новая задача или fork внутри того же старого фонового хоста не является границей перезагрузки каталога,
поэтому карточка остаётся видимой, пока проверка состояния не обнаружит актуальный воркер. Если вместо
этого дашборд сообщает, что каталог имеет состояние pending или unknown либо управляемая маршрутизация
не внедрена, выберите там **Применить к Codex**, чтобы сначала согласовать и проверить эти файлы.
Закрыть и снова открыть ChatGPT для такого исправления недостаточно.

Для уже согласованного каталога с устаревшим воркером действие дашборда/API
**Принудительно перезапустить воркеры**
и CLI остаются расширенными запасными вариантами. Они повторно синхронизируют состояние, используют
проверку по желаемой ревизии, посылают сигнал только точно совпавшим процессам текущего пользователя
`codex … app-server` и `codex-code-mode-host` и никогда не переходят к широкому `pkill`. Поскольку этот
путь обходит обычный жизненный цикл приложения ChatGPT, оно может показать **stopped unexpectedly**.
Форма CLI:

```bash
ccx sync --restart-codex
```

## Аутентификация и конфиденциальность

Компаньон не создаёт отдельную систему входа, не использует macOS Keychain и не читает оттуда
учётные данные провайдеров.

Текущие версии CodexCommander создают независимые учётные данные управления в
<code>~/.codexcommander/admin-api-token</code> (или
<code>$CODEXCOMMANDER_HOME/admin-api-token</code>). Компаньон читает этот существующий файл через
проверенный файловый дескриптор без перехода по символическим ссылкам, хранит значение только
в памяти процесса и отправляет его только процессу CodexCommander на loopback-интерфейсе, прошедшему
проверку идентичности. Он никогда не показывает, не журналирует, не копирует и не сохраняет
токен и не помещает его в URL браузера.

Когда компаньон открывает дашборд, он запрашивает у проверенного локального прокси краткоживущий одноразовый launch-ticket. Ticket находится только во fragment URL и удаляется во время однократного обмена; постоянный admin-token не попадает в URL или Web Storage. Подтверждённая полнофункциональная сессия хранится только в памяти процессов до восьми часов и не продлевается. После истечения срока или перезапуска прокси следующий API-запрос получает `401`, и страница предлагает открыться заново через компаньон или `ccx gui`. Вручную открытый loopback-дашборд не получает API-сессию и никогда не запрашивает и не отправляет постоянный admin-token.

Учётные данные провайдеров остаются под управлением CodexCommander. Компаньон никогда не читает
токены ChatGPT, Kimi, Grok, Anthropic или других провайдеров и никогда напрямую не вызывает
эндпоинты входа провайдеров.

Установка, настроенная только с помощью <code>CODEXCOMMANDER_ADMIN_AUTH_TOKEN</code>, работает, когда
эта переменная наследуется процессом приложения. Приложения, запущенные из Finder, обычно не
наследуют переменные оболочки; если защищённого файла токена нет, компаньон сообщает, что
аутентификация управления недоступна, вместо того чтобы показывать форму ввода токена.

Записи об активных запросах хранятся только в памяти. Ответ управления содержит эфемерные в
рамках процесса идентификаторы строк, идентификаторы провайдеров/моделей, временные метки и
агрегированные счётчики. В нём нет промптов, заголовков, рабочих каталогов, аргументов
инструментов, идентификаторов аккаунтов, учётных данных, тел запросов, исходных идентификаторов
потоков/сессий или истории активности.

## Опрос

Когда панель открыта, приложение часто обновляет лёгкие данные о выполняющихся запросах, а после её
закрытия снижает частоту. Квоты провайдеров обновляются отдельно и реже, с использованием
временных меток источника, сообщаемых CodexCommander. При повторных сбоях задержка автоматически
увеличивается, а перекрывающиеся обновления объединяются.

Используйте **Обновить**, чтобы немедленно обновить выполняющиеся запросы и принудительно обновить квоты.

## Сборка из исходного кода

Требуются macOS 13 или новее и Xcode Command Line Tools. Для универсальной сборки под Intel + Apple silicon требуется полная версия Xcode.

```bash
cd /path/to/CodexCommander
bun install
bun run test:macos
bun run build:macos
open dist/macos/CodexCommander.app
```

Приложение для разработки находится ровно в `dist/macos/CodexCommander.app`. Каждая сборка встраивает
среду Bun и ресурсы сервера CodexCommander в пакет приложения; запущенное приложение не выполняет
`src/` непосредственно из checkout. Чтобы применить изменения исходников, пересоберите приложение.
Оставляйте его там во время разработки и не копируйте в Application Support. При двойном щелчке,
который запускает новый процесс приложения, оно выполняет явный Start, запускает прокси или
подключается к нему и направляет управляемый Codex через него; внешний провайдер пользователя сохраняется.
При сбое или работе офлайн приложение не закрывается: панель и кнопка **Start**
остаются доступными.
Каждая сборка записывает точную ревизию Git в `CodexCommanderSourceRevision` файла `Info.plist` внутри
пакета и печатает её после сборки. Для незакоммиченного исходного кода добавляется `-dirty`, поэтому
перед финальной сборкой сначала создайте коммит.

## Устранение неполадок

- **Прокси недоступен** — запустите его командой <code>ccx start</code> или установите фоновую
  службу командой <code>ccx service install</code>.
- **Аутентификация недоступна** — выполните <code>ccx doctor</code>; убедитесь, что каталог
  состояния CodexCommander и <code>admin-api-token</code> принадлежат вашему пользователю и недоступны
  для группы и остальных пользователей.
- **Квота недоступна** — откройте раздел **Управление** нужного провайдера и подключите или
  повторно аутентифицируйте аккаунт. Если Grok показывает **Требуется обновить вход**, завершите вход
  командой <code>grok</code>, затем нажмите **Обновить** в CodexCommander; для Kimi используйте
  <code>kimi</code>. Некоторые провайдеры не предоставляют API квот.
- **Не удалось восстановиться после перезапуска** — откройте **Logs** и выполните
  <code>ccx status</code>. Компаньон никогда не завершает процесс принудительно и не
  перезаписывает состояние службы в качестве запасного варианта.
- **После остановки, обновления Codex или холодного запуска видны только нативные модели** — снова
  откройте CodexCommander. При запуске каталог синхронизируется автоматически, а если обнаружение
  провайдеров временно вернуло пустой результат, всё ещё настроенные маршрутизируемые модели
  восстанавливаются из защищённого последнего рабочего каталога. Если карточка **Restart ChatGPT to
  load models** остаётся видимой, завершите и снова откройте ChatGPT, а затем начните новую задачу.
  Используйте расширенный запасной вариант дашборда/API или CLI из раздела
  [Обновления каталога агентов](#обновления-каталога-агентов), только если ручной перезапуск не подходит.

## Удаление

Выключите **Launch at Login**, завершите работу компаньона и переместите <code>CodexCommander.app</code>
в Корзину. Он не хранит учётные данные провайдеров и не создаёт записей Keychain. Удаление
компаньона не останавливает и не удаляет прокси CodexCommander. Выполните отдельно
